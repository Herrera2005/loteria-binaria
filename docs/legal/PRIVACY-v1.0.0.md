# Política de Privacidad — Lotería Binaria

Versión: 1.0.0  
Fecha efectiva: 26 de julio de 2026

## 1. Alcance

Esta política describe el tratamiento de información dentro del proyecto
académico Lotería Binaria.

## 2. Información tratada

El sistema puede tratar:

- Identificadores de cuenta.
- Correo electrónico y nombre de usuario.
- Datos de perfil.
- Información de verificación.
- Direcciones IP y agentes de usuario transformados mediante hash.
- Información de sesiones y dispositivos.
- Operaciones financieras y contables.
- Participaciones, boletos, sorteos y reclamos.
- Registros de seguridad y auditoría.

## 3. Finalidades

La información se utiliza para:

- Crear y proteger cuentas.
- Validar identidad y permisos.
- Procesar operaciones.
- Prevenir fraude y abuso.
- Mantener trazabilidad contable.
- Resolver reclamos.
- Cumplir reglas del sistema.
- Investigar incidentes de seguridad.
- Mejorar la estabilidad de la plataforma.

## 4. Minimización

La plataforma debe almacenar únicamente la información necesaria para cada
proceso.

Los datos sensibles deben mantenerse separados de las credenciales cuando el
modelo de datos lo permita.

## 5. Protección

El sistema contempla medidas como:

- Hash de identificadores y datos técnicos.
- Cifrado de datos personales definidos como confidenciales.
- Control de acceso por roles y permisos.
- Registro de acciones administrativas.
- Separación entre información pública y privada.
- Restricción de acceso directo a secretos.

## 6. Datos financieros

Los movimientos financieros se conservan para trazabilidad, conciliación,
auditoría y resolución de errores.

Los informes públicos no deben mostrar información que permita identificar a
los usuarios.

## 7. Archivos y evidencias

Los documentos y evidencias pueden almacenarse en un servicio de objetos con
metadatos de integridad, estado y acceso controlado.

## 8. Conservación

La información se conserva mientras sea necesaria para el funcionamiento,
seguridad, auditoría, resolución de reclamos o cumplimiento de obligaciones.

## 9. Derechos y solicitudes

Los mecanismos para consultar, corregir o solicitar tratamiento sobre datos
personales deberán implementarse antes de la operación pública del sistema.

## 10. Cambios de versión

Cualquier modificación material debe publicarse como una nueva versión. El
sistema conserva qué versión fue aceptada por cada usuario.

## 11. Naturaleza académica

Esta versión corresponde al desarrollo académico inicial y debe ser revisada
por un profesional jurídico y de protección de datos antes de cualquier
operación real o comercial.
